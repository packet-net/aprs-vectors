# Review findings: aprs-vectors PR #29 (experiments in /tmp/r4-review-vectors/), with the coordinator's rulings

1. HIGH, build form unchecked and under-pinned. schema.json accepts any `report` string and any args; check.py passed with report "telemetree", arg "sequnce", a build case expecting `info`, an encode case expecting `tnc2`. README Build records table lacks the values of mic_e_message, a key for a Mic-E device type, and what an absent `station` means. Only 5 build cases, pinning 2 of about 14 defaults in DEFAULTS.md.
   RULING: tighten schema.json (enum of reports; per-report allowed arg keys and types; expect form per input form) and check.py; complete the README table; add a build case for EVERY row of DEFAULTS.md (differing and agreeing): Mic-E `'` and off duty, `!` and `/` without messaging, APZ001 and no path, weather `/_` with unknown dots, Mic-E speed 0, object and positionless weather with no timestamp refused missing-field, no symbol refused invalid-symbol, alive, metadata addressee, no ambiguity, uncompressed, no message id, five empty analog channels, bits 00000000.

2. HIGH, `implementation-limit` and `via` can hide a disagreement. A dump claiming implementation-limit on a 300-byte status compared as "agree"; "via":"tool" is never shown or counted.
   RULING: an implementation-limit record names its limit in a `limit` key (`information-field`, `path`, `capabilities`, `weather-extras`, or another name the library documents) and each fixed-capacity library publishes its capacities in a small machine-readable file in its repo (aprs-c: limits.json). compare.py takes `--limits <dump-index-or-name>=<file>` and FAILS (counts as a difference, bucketed) when a record claims a limit the input does not exceed, for the limits it can compute from the input (information field bytes, path entries, capability items, extra weather fields if cheap; otherwise count and print by limit). compare.py prints the count of `"via":"tool"` records per library beside the result and in --json. A library's test runner fails, not skips, when a case gives implementation-limit for input within its stated capacities.

3. MEDIUM, `too-long` sits in two places in the order (a field's own limit before padding-space; the whole-field size last), and a tool cannot tell which a library returned.
   RULING: the size refusal gets its own id, `information-field-too-long`: a record with no other fault whose information field as written exceeds 256 bytes. `too-long` keeps its one place and meaning (a field over its own limit). codes.json refusals 26 -> 27; README Refusal reasons, Encoding, "One quantity, one value", interpretations.md and every size case updated; a decoded packet over 256 bytes re-encodes refused with `information-field-too-long`.

4. MEDIUM, run-on weather reasoning. The two corpus packets it changes (corpus/0509 `g001068r000`, corpus/1227 `s0100048r000`) are senders that dropped a field letter, and in 0509 the rule drops a valid gust of 1.
   RULING: keep the rule; state the trade in interpretations.md: a run of digits longer than the field holds cannot be split with certainty, the old reading reports a value the sender may never have sent (214 F) and loses every later field, the new one reports nothing uncertain and keeps the later fields; a decoder never reports a value the sender did not send. Also pin "the end": the run-on rule's "end of the information field" means the end of the weather text, that is the end of the field or the start of a trailing element the Weather rule lifts first (base-91 telemetry, a !DAO!) in a positioned report. Add cases `...t2147483647!W5!` and one with trailing `|..|` telemetry (value dropped, out-of-range-value).

5. MEDIUM, stale claim: README Refusal reasons says value-given-twice has no case; check.py EXEMPT_REFUSALS likewise. Fix both.

6. LOW: interpretations.md and mic-e/altitude-with-no-form-before-a-type-code say 231,913 metres; `>4W` is 231,932 m (760931.76 ft). Fix.

7. LOW, control characters. RULINGS: say APRS12c ch. 5 forbids CR/LF at the end and is otherwise silent; C1 bytes are not judged (only bytes below 0x20 and 0x7F; a byte 0x80-0x9F is either part of UTF-8 or covered by non-utf8-text); the text before `!` in a position-not-at-start report is not judged (it is discarded, not text); a control character in a capability token and in a value: keep as is but state it; write the exception that a third-party packet's inner field is carried as received, so an inner control character re-encodes identical.

8. LOW: say in interpretations.md that the 256-byte limit also binds a program that only sends to APRS-IS, deliberately: a packet may be gated to RF, and APRS12c notes longer comments are seen but gives 256 as the field.
