# Review findings to fix: aprs-cs (probe in /tmp/r4-review-aprs-cs/)
1. Medium. A tool-made refusal is unmarked: in `diff build`, a telemetry recipe with no sequence gets missing-field from a placeholder the tool fills in (tests/Packet.Aprs.Tests/Vectors/RecipeBuilder.cs:173-192) with no `"via":"tool"`. Mark every tool-made refusal; say so in docs/aprs-validation.md's build paragraph.
2. Medium. A path entry of only `*` (Tnc2Codec.cs:91) now makes an OUTER header unusable even in Lenient: `AprsPacket.Decode("N0CALL>APZ001,WIDE1-1*,*,WIDE2-1*:>x")` throws. The reviewer read (did not run) that 1.1.0 accepted it with EmptyPathEntry. First establish what the published 1.1.0 package really does for that line and what the other five libraries do (aprs-py and aprs-go in /home/tf/src/aprs-r4 give invalid-address for the outer header). If 1.1.0 differed, list it under breaking changes; if it did not, say nothing changed for the outer header.
3. Low. CHANGELOG licence line must say: MIT from this release; versions up to 1.1.0 were published under AGPL-3.0-or-later.
4. Low. CHANGELOG names the vectors pin c423a29; state the real pin.
5. Low. `ToData()` on a builder with no symbol used to throw InvalidOperationException and now quietly returns data with default(AprsSymbol) (AprsBuilder.cs:250). Make it refuse as Build() does (AprsEncodeException InvalidSymbol), and say so in the CHANGELOG.
6. Low. `diff build` crashes the whole run on an ack or reject recipe with no addressee (ArgumentNullException; only two exception types are caught, RecipeBuilder.cs:54/152). The LIBRARY should not throw ArgumentNullException for a missing addressee from a builder either: it must be an AprsEncodeException with the right refusal code (invalid-addressee: absent text is empty text). Fix the library, then the tool needs no special catch.
7. Low. Four README-example tests fail under de-DE and tr-TR because the test code formats decimals in the current culture ("12,9 V"). Make the examples and tests culture-invariant (the README should show code that prints the same everywhere).
