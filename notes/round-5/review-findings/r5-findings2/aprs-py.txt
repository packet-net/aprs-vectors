Second-review findings for aprs-py (verdict: merge after fixes; all first findings confirmed fixed). Fix all; add a regression test for each using the reproducer.
N1 (serious: bytes that do not read back as the data given). An infinity compares equal to any finite number: src/pdn_aprs/_util.py:134-137 number_equal (abs(inf-x) <= 1e-9*inf is true), reached via _readback.py:147-153; the not-a-number check runs only after a refusal (encode.py:255-260, 2009-2013), so an encoder that never writes the number itself returns bytes. Repro 1: build_packet("N0CALL", NmeaSentence(sentence="GPGGA,123519,4807.038,N,01131.000,E,1,08,0.9,545.4,M,46.9,M,,*47", has_checksum=True, latitude=float('inf'))).to_tnc2() writes the line (decodes to 48.1173); altitude_m and longitude the same. Repro 2: a decoded inner third-party packet replaced with latitude=inf, course_degrees=-inf or telemetry sequence=inf writes `}X>APRS:!5130.00N/...`. Fix: refuse every non-finite number up front, at every depth, in every numeric field of every type (walk the data generically so no field can be missed), AND make the comparison treat a non-finite value as unequal to everything. Extend the existing non-finite sweep test to cover NMEA fields, inner packets and telemetry.
N2. Mic-E legacy_telemetry given as floats crashes with TypeError (encode.py:1305-1310): (1.0,1,2,3,4) is the whole numbers; (0.5,...) is value-out-of-range. Audit every other integer or code field for the same (a whole number given as a float is that number; a fraction is value-out-of-range; never an unexpected exception type from any public encode or build call: add a sweep test that feeds float, Decimal, Fraction, bool, None, str and huge ints to every numeric field and asserts only EncodeError or success).
N3. repr is not total: repr() of a ThirdParty chain 3000 deep raises RecursionError; and MicEReport.altitude_in_comment is repr=False although it changes the bytes. Make repr and str total (iterative or depth-capped with an ellipsis) and show altitude_in_comment.
N4. TestData("a\rb") is invalid-character (encode.py:1901) while user-defined data with the same byte is written: by the rule only data ENDING in CR or LF is invalid-character and an information field written alone is not judged for CR or LF inside. Check the README at the pin and make test data follow it.
N5. CHANGELOG gives the vectors pin twice (f52e038 and stale 29298ee).
N6. to_kiss(1.5) raises TypeError and to_kiss(True) is accepted: validate the port argument (ValueError or EncodeError as the API documents). Station(path="A,,B") silently drops the empty entry while build_packet refuses it as invalid-address: make them agree (refuse).
