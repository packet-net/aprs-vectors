1. A non-finite number must be not-a-number before every later code (must fix)

About 130 faults lines per seed. You give a later code where the other five give not-a-number, in two ways:
- the count is checked before the values: 16 EQNS coefficients with a NaN among them gives too-long;
- a non-finite value in a list item beyond what the C field holds (a sixth analog value in a telemetry report, comment telemetry, Mic-E telemetry, inner data) is never seen, so the comment's invalid-character, the count's too-long, a latitude's value-out-of-range, a symbol's invalid-symbol, a DAO's invalid-code and so on win.

Rule: README Refusal reasons order "... invalid-timestamp, not-a-number, value-out-of-range, value-has-no-form, invalid-code, invalid-symbol, invalid-character, too-long, ..."; Read-back "a non-finite number is not-a-number wherever it is, never compared as absent"; Comparing implementations: NaN or infinity is a code "its value alone decides" for an input the implementation cannot hold, and the dump tool reports it.

Fix: before any other data check, look at every number given, at every depth and in every list item including items past the C capacity, and refuse not-a-number if one is NaN or infinite. Where the library cannot hold the surplus item, the dump tool must see it and report not-a-number ("via": "tool" is fine).
